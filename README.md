# Metamegn Command Center v2

> **Independent public-source illustration. Not a PSS system. No PSS, bank or merchant data. Sample data only.**
> **Top Banner: "Demo data, no live payments"**

---

## 1. What This Is, and What It Is Not

Metamegn is a **UI illustration on mock data** of one research question:
> *"Could a bank-scoped transaction recording and exception routing layer solve cash/digital merchant discrepancy bottlenecks, and would an acquiring commercial bank pay for it?"*

### Critical Distinctions
- **It is NOT a product, NOT a proposal, and NOT a PSS system.**
- **No affiliation:** Does not use the name, logo, colours, or wording of PSS, any bank, Telebirr, Chapa, M-Pesa, or any provider as if affiliated. All rails use neutral designations (*Wallet Rail A*, *Bank Rail B*, *Interoperable QR*, *Card Tap (SoftPOS-style)*, *Cash*).
- **No live data:** No real names, phone numbers, bank account numbers, API keys, or credentials. All numbers and records are generated by a deterministic seeded generator.
- **Evidence status chips:** Every screen, table, metric, and feature bears an explicit evidence tag (`Sample data`, `Assumption`, `Not tested`, or `Needs approval`). Nothing is ever labeled "Verified" or "Live".

## 2. Scope Boundary

```
┌────────────────────────────────────────────────────────────────────────┐
│                        METAMEGN SCOPE BOUNDARY                         │
├──────────────────────────────────┬─────────────────────────────────────┤
│      IN-SCOPE (ILLUSTRATION)     │        STRICTLY OUT-OF-SCOPE        │
├──────────────────────────────────┼─────────────────────────────────────┤
│ ✔ Event ledger recording         │ ✘ Money movement or fund transfers  │
│ ✔ Statement matching rules       │ ✘ Payout scheduling or balance held │
│ ✔ Exception categorization       │ ✘ Cardholder PAN/PIN storage        │
│ ✔ Offline queue & replay sync    │ ✘ KYC / Merchant underwriting       │
│ ✔ Shift counting & cash variance │ ✘ Proprietary PSS/Bank affiliation  │
│ ✔ Audit trails & role RBAC       │ ✘ Live external network calls       │
└──────────────────────────────────┴─────────────────────────────────────┘
```

The system **records events, reconciles reports, and routes exceptions. It does NOT move money, approve KYC, hold funds, or settle.** No screen offers a payout, a transfer, or a balance that implies custody.

## 3. Architecture & Seam Design

```
src/
├── domain/            # Types, integer minor units (ETB cents), permissions, evidence, 5-class matching
├── data/              # EventSourceAdapter interface seam, MockAdapter, Mulberry32 PRNG, offline queue
├── features/          # capture/ (360px Cashier POS), ledger/, reconcile/, options/, shifts/, reports/, staff/, about/
├── ui/                # Layout, UniversalNotice, EvidenceChip, StateViews (empty/loading/error)
├── i18n/              # English (default), Amharic, Afaan Oromoo + Noto Sans Ethiopic
└── app/               # Routes, RouteGuard, and App entry point
```

### The Architectural Seam
The presentation layer communicates strictly through the `EventSourceAdapter` seam. Only `MockAdapter` is implemented. The UI never imports raw mock objects directly. See `docs/ADAPTER.md` for the prerequisite gates (legal, data protection, security, and written consents) that would precede any production adapter.

## 4. How to Run

### Installation & Dependencies
The project includes an `.npmrc` file configured with `legacy-peer-deps=true` to seamlessly resolve React 19 dependencies with ecosystem tooling.

```bash
# Standard install (uses repository .npmrc automatically)
npm install

# Alternatively, if running in an environment without .npmrc support:
npm install --legacy-peer-deps
```

### Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

### Run Unit Tests
```bash
npm run test
```
Executes Vitest covering integer money arithmetic, permissions, all five reconciliation matching classes, the capture state machine, offline queue replay, and options explorer invariants.

### Production Build
```bash
npm run build
```

## 5. "How to Present It" (Demonstration Script for Evaluators)

When demonstrating this research illustration to stakeholders, engineers, or evaluators:

1. **Start on the Reconciliation Hub (`/reconcile`)**:
   - Point out the **top demo banner** (*"Demo data, no live payments"*) and the **sticky footer disclaimer** on every route.
   - Highlight the **Match rate** (94.2%), the **Open Exceptions** count, and the **Evidence chips** (`Sample data`).
   - Explain the 5 discrepancy classes: *Matched*, *Missing at Provider*, *Missing at Till*, *Amount Mismatch*, and *Duplicate*.
   - Click **"Triage"** on an open exception to demonstrate how supervisors record resolution rationale into the append-only audit trail.

2. **Demonstrate the Cashier POS (`/pos`)**:
   - Show that the keypad functions at mobile widths (360px viewport).
   - Enter an amount (e.g. ETB 150.00) and choose a neutral payment rail (e.g., *Wallet Rail A* or *Interoperable QR*).
   - Note that the generated slip immediately displays *"Recorded, awaiting provider report"*—it never shows "paid" without an external statement match.
   - Toggle **"Simulate Offline Mode"**, capture another transaction, and show that it queues locally. Toggle back online and click **"Replay"** to show deduplication and synchronization.

3. **Demonstrate Shift Register Handover (`/shifts`)**:
   - Open a shift close modal. Enter a counted cash figure and show the live variance calculation (Over / Short / Balanced) without any fund transfer.

4. **Review Governance & Audit (`/staff`)**:
   - Switch between **Cashier**, **Supervisor**, and **Manager** using the top header control labeled *"Demo role switcher, no authentication"*.
   - Demonstrate route guards blocking unauthorized actions.
   - Inspect the immutable audit log recording every event capture, void, and resolution.

5. **Review About & Proof Gates (`/about`)**:
   - Walk through the Scope Boundary table.
   - Review the **Four Proof Gates** (Bank buyer, legal permissions, finance acceptance, security review), explaining that all are explicitly marked `Not started`.
   - Note that the application illustrates Option B of five strategic paths kept open.

6. **If asked about alternatives, show Options Explorer (`/options`)**:
   - Say: *"The method keeps five options open, including doing nothing new."*
   - Point out the fixed top notice: *"Option B is the first hypothesis to test. No option is chosen. None can be chosen until the four proofs exist and the hard legal, security and commercial gates are passed. Hard gates override any score."*
   - Note that Option E (*No new platform*) has identical visual weight and structure to Options A through D.
   - Demonstrate the equal five-column layout, the two-option mobile compare selector (starts unselected), and the accessible presenter walkthrough (`Esc` to close).
   - Review the 5-stage gate strip (`Screening`, `Feasibility gate`, `Non-production validation`, `Live pilot gate`, `Scale gate`) and the five pivot condition sentences—all marked with `Assumption` and `Not started` in neutral grey.
